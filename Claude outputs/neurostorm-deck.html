01 · Why this task

Mental imagery as a communication channel

The task asks a person to imagine one of three things on cue: playing tennis, navigating around their house, or squeezing a hand. Each produces a distinct, decodable pattern of brain activity — which is precisely what makes this the classic paradigm for detecting covert command-following: evidence that someone is following instructions even when they can't otherwise respond.

Before a decoder like this can be trusted on someone who can't confirm whether it worked, it has to be validated on people who can perform the task reliably and overtly. That's what this 26-subject dataset is for — and what this whole analysis builds toward.

01 · The model

What NeuroSTORM actually is

A general-purpose foundation model for fMRI (Wang et al., Nature Biomedical Engineering, 2026) — pretrained once, then adapted to many downstream tasks.

Backbone

Shifted-Window Mamba (SWM): a state-space model with window attention, built to process raw 4D fMRI volumes directly — no ROI/atlas reduction, linear-time cost instead of full self-attention.

Pretraining

Masked-autoencoding on 28.65M fMRI frames from 50,000+ participants — reconstructing masked voxels from spatiotemporal context. No task labels used.

Adaptation

Task-specific Prompt Tuning (TPT): a small set of learnable prompt tokens can adapt the frozen backbone to a new task, updating <5% of parameters.

Wang, C. et al. "Towards a general-purpose foundation model for functional MRI analysis." Nat. Biomed. Eng. (2026).

02 · A real dimensionality issue

20 frames in, 32 frames needed

NeuroSTORM's pretrained temporal position embeddings were built for 20-frame sequences. Our blocks need a 32-frame window to fully cover one imagery period. At load time, the model stretches its own learned time embeddings to fit:

[ckpt] interpolated pos_embeds.0.time_embed: T=20 -> T=32 [ckpt] interpolated pos_embeds.1.time_embed: T=20 -> T=32 [ckpt] interpolated pos_embeds.2.time_embed: T=20 -> T=32 [ckpt] interpolated pos_embeds.3.time_embed: T=20 -> T=32

What a position embedding does

It tells the model "this frame is 3rd of 20," etc. Interpolating it to T=32 stretches that learned pattern onto a longer timeline, rather than learning time-position from scratch.

not a bug
This is a standard, well-behaved adaptation — logged automatically, not an error to chase.

bug found

The default splitter always gave the same fold

The codebase's built-in random splitter hardcodes np.random.seed(0) — so asking for 5 different folds silently regenerated the identical split five times.

Fix: a small script writing real subject-level fold rotation directly — 5 disjoint test groups, each subject held out exactly once.

bug #1

A metrics bug was masking the real signal

Before any of this: test/val AUROC was flatlining at a literal 0.0 by epoch 11 — not chance, zero.

Root cause

The evaluation code averaged a subject's logits across all their blocks — spanning all 3 classes — then compared that average to only the first block's label. Correct for one-label-per-scan tasks; meaningless for our 30-label-per-scan design.

Fix

Added a dedicated per-block multiclass branch: accuracy, AUROC and a confusion matrix computed directly per block, plus per-class predicted-fraction logging — all streamed to TensorBoard.

bug #2 · root cause

One number was hiding each subject's fingerprint

global_mean = data[~background].mean() global_std = data[~background].std() data = (data - global_mean) / global_std

This is one scalar mean and std for a subject's entire scan — not per voxel. It removes one overall offset and scale, but any spatially-varying pattern — this subject's motor cortex reads relatively brighter than their visual cortex, for anatomical, registration, or coil-sensitivity reasons — survives identically on every single frame and every block.

That static per-subject "fingerprint" is exactly what a spatially-aware model would pick up on first — swamping the much subtler task-locked signal.

fix

Remove each subject's own per-voxel mean

For each subject: dequantize their scan, compute their own per-voxel mean across the whole ~1,145-frame recording (one fixed baseline, can't leak any block's label), subtract it, then re-quantize. Written to a new dataset folder — the original is untouched.

A tradeoff to reason through, first

Will the pretrained backbone tolerate this?

The pretrained model has only ever seen the old normalization. Removing each subject's anatomical structure is a real, non-trivial shift in input statistics relative to pretraining.

prompt — highest risk

98.4% frozen. Can't adapt patch embeddings to new input statistics at all.

prompt_ln — still exposed

98.2% frozen; only LayerNorm affine terms can adjust.

none — best positioned

Every parameter can re-adapt to the new distribution.

Decision: test full fine-tuning first. If it clears chance convincingly, the normalization fix is validated and the shift wasn't fatal.

08 · Where we stand

Confirmed, and what's still open

Confirmed

  • Real task-locked imagery signal exists in these blocks
  • Root cause of the collapse was global vs. per-voxel normalization
  • Full fine-tuning on corrected data reaches 0.88 AUROC — fold 1

Open questions

  • This is one fold of five — needs cross-validated confirmation
  • Full fine-tune on 15 subjects risks overfitting, with no cheaper fallback (prompt-tuning doesn't work here)
  • Partial fine-tuning (unfreeze early layers only) is an untried middle ground

Why not leave-one-out CV instead?

Considered and set aside: 26 full-backbone runs vs. 5 for uncertain benefit; our 5-fold split already tests every subject exactly once; a 1-subject test fold (~30 blocks) is noisier per-fold than a 5-6 subject one, not more robust.
